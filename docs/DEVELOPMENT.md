# 構成と検証範囲

## 構成

- `lib/domain`：服用予定、在庫台帳、残数・遅延の計算
- `lib/application`：保存データと通知・画面の制御
- `lib/services`：端末内保存、通知、PDF、添付メール
- `lib/ui`：カレンダー、薬の管理、報告、設定
- `android`／`ios`：各OSのアプリ設定
- `vendor/fln`：通知ライブラリのローカル修正版。Androidの通知本文と角丸ボタンの差分を含みます
- `test`：ロジック・画面・移行・通知・メールのテスト。架空データだけを使用します
- `tool`：iOSのID設定・ビルド補助

## 検証

GitHub用に整理したソースで、Windows上の解析と**148項目**のテストが成功しています。iPhone向けの追加4項目は、通知権限の状態読取、初期化時の許可要求抑制と明示要求、64件の予約、Androidの100件保持を確認します。OSとのやり取りはテスト用の応答で確認しており、実際のiPhoneでの動作確認ではありません。

配布用Android APKは前回確認済みの0.8.0+15をそのまま使用しています。Android 12エミュレーターで更新時のデータ保持・新規起動・表示を確認済みです。今回のGitHub用ソースではiOS側の設定と通知処理を追加し、Android向けの予約数・画面・保存処理は維持しています。この資料準備ではAndroid APKの再ビルドはしていません。

GitHub ActionsはまだGitHubへアップロード・実行していません。iOSのコンパイル、Simulator実行、実機、署名、TestFlightは未確認です。これらを済ませるまではiPhone版の配布準備完了とは扱いません。

画像比較は同梱のフォントとWindowsで作成した基準画像を使用します。他のOSで画像比較だけに差が出た場合は、内容を目視して判断してください。CIの通常テストはWindowsで実行する設定です。

## 署名とID

Androidの既存アプリIDと更新用の署名は配布APKで継続しています。秘密の署名ファイルはこのリポジトリにありません。CI等で新しく生成した別の鍵のAPKを、既存利用者への更新として配らないでください。

iOSは未登録の仮ID`com.example.malariacare`です。登録済みの固有IDとApple Teamを`tool/configure_ios.py`で設定します。証明書・パスワード・プロビジョニングをGitへ追加しないでください。
